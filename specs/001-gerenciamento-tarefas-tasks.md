Registrar as decisões na spec e no plano. **Pronto quando:** as aprovações constarem da spec e do plano e as questões em aberto estiverem resolvidas. **Dependências:** nenhuma.

- [x] **Definir o domínio e validar seus schemas.** Criar tipos de tarefa/estado/filtro, schemas Zod de criação, título, ID UUID v4 e filtro, e classe de erro de domínio para tarefa não encontrada. **Pronto quando:** testes `node:test` cobrirem título ausente, vazio, aparado, limites de 1 e 200 caracteres, título acima do limite, UUID v4 e filtros válidos/inválidos, e `npm run typecheck` passar. **Dependências:** confirmar e registrar as decisões de contrato.

- [x] **Implementar o armazenamento em memória.** Criar a interface do store e a implementação para inserir, obter, listar, atualizar estado e remover tarefas; gerar IDs UUID v4 únicos no armazenamento e manter ordem de criação. **Pronto quando:** testes provarem operações de armazenamento, unicidade dos IDs, filtros por estado, ordem de criação, proteção contra mutação externa e comportamento para IDs inexistentes, e `npm run typecheck` passar. **Dependências:** definir o domínio e validar seus schemas.

- [x] **Implementar criação e listagem no serviço.** Adicionar casos de uso para criar tarefas abertas com título normalizado e listar por `all`, `open` ou `done`, considerando `all` como filtro padrão. **Pronto quando:** testes unitários cobrirem criação, normalização e cada filtro, e `npm run typecheck` passar. **Dependências:** implementar o armazenamento em memória.

- [x] **Implementar conclusão e remoção no serviço.** Adicionar casos de uso para concluir tarefas de forma idempotente e remover tarefas, traduzindo IDs inexistentes em erro de domínio. **Pronto quando:** testes unitários confirmarem repetição da conclusão sem regressão, remoção, ausência em listagens após remoção e erros explícitos para IDs inexistentes/removidos, e `npm run typecheck` passar. **Dependências:** implementar criação e listagem no serviço.

- [x] **Criar a composição compartilhada da aplicação.** Implementar uma fábrica de dependências que componha store e serviço, permitindo injetar a mesma instância do serviço nos adaptadores HTTP e CLI durante testes. **Pronto quando:** testes verificarem a composição e a possibilidade de compartilhar a mesma instância de serviço; `npm run typecheck` passa. **Dependências:** implementar conclusão e remoção no serviço.

- [x] **Implementar a interface HTTP.** Criar o servidor com `node:http`, validar entradas com Zod na fronteira e expor criação, listagem, conclusão e remoção conforme os contratos aprovados, traduzindo erros de domínio para respostas explícitas. **Pronto quando:** testes de integração cobrirem os sucessos e erros definidos na spec e nos contratos aprovados, inclusive filtro padrão, filtro inválido e JSON inválido, e `npm run typecheck` passar. **Dependências:** criar a composição compartilhada da aplicação.

- [x] **Implementar a interface CLI.** Criar os comandos de criação, listagem, conclusão e remoção conforme a sintaxe aprovada, validar argumentos com Zod, apresentar erros explicitamente e usar os códigos de saída definidos. **Pronto quando:** testes cobrirem cada comando, filtros, entradas inválidas, ID inexistente, saída de erro e códigos de saída aprovados, e `npm run typecheck` passar. **Dependências:** criar a composição compartilhada da aplicação.

- [x] **Conectar as entradas de execução HTTP e CLI.** Configurar `src/index.ts` para iniciar o servidor e `src/cli.ts` para executar a CLI, usando a composição compartilhada sem misturar responsabilidades entre camadas. **Pronto quando:** `npm run dev` iniciar o servidor e `npm run cli` encaminhar os argumentos para a CLI, com testes ou verificações de execução cobrindo ambas as entradas; `npm run typecheck` passar. **Dependências:** implementar a interface HTTP; implementar a interface CLI.

- [x] **Executar a verificação final da feature.** Rodar a suíte completa e a verificação de tipos depois da integração das duas interfaces. **Pronto quando:** `npm test` e `npm run typecheck` terminarem com sucesso, cobrindo o comportamento funcional especificado sem enfraquecer testes existentes. **Dependências:** conectar as entradas de execução HTTP e CLI.
